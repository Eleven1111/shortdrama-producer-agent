# P1 渲染回环

验证一件到目前为止**零证据**的事：agent 产出的 prompt，真实出片效果到底如何。

在此之前所有质量判断都停在 prompt 文本层（结构齐不齐、约束够不够），从未与
Seedance 的实际出片对齐过。**没有这一环，「商用级」永远是 UNVERIFIED。**

## 这不是 agent 的功能

agent 的运行时边界不变 —— 它仍然只产出 prompt，不调渲染 API（见 SKILL.md / AGENTS.md
的 Boundaries）。本目录是**开发期评测工具**，给维护者验证质量用。

## 首个实验：Step 5.5 到底有没有用

`references/iteration-lessons.md` 的约束是从 4,154 组真实修订里统计出来的，
但「创作者反复补它」不等于「补了出片更好」。A/B 直接测：

| 组 | 内容 |
|---|---|
| **A** | 完整工作流，含 Step 5.5 约束加固 |
| **B** | 同一需求，跳过 Step 5.5，其余相同 |

12 用例 × 2 组 = 24 次渲染。用例见 `cases.json`，每个带 `probes` 字段标明该用例
重点探测哪几条约束。

## 流程

```bash
python3 run_ab.py --prepare                 # 1. 生成 24 个待填槽位
#    2. 让 agent 逐条填 prompt 字段（A 组走完 Step 5.5，B 组跳过）
python3 run_ab.py --render --backend manual --model <模型版本> --ratio 9:16 --duration 8
python3 run_ab.py --sheet                   # 4. 生成盲测评分表
#    5. 按 rubric.md 评分（评分者看不到组别）
python3 aggregate.py                        # 6. 还原组别并聚合
```

第 2 步由被测 Agent 产出 prompt。人工回填成片后，再运行一次 `--render --backend manual`
更新成片状态，然后生成评分表。

评分者只接收 `out/grading_sheet.json`、其中引用的 `blind-videos-*` 目录和统一评分口径。
视频路径相对于评分表，文件名为 `S001.mp4` 等。重跑 `--sheet` 会重建匿名映射和空白评分表，
因此请在开始评分前冻结本轮评分表。聚合报告会列出缺成片、缺项或缺组别的用例。

## 三种渲染后端

| backend | 说明 |
|---|---|
| `dry` | 不调 API，只验证管道结构。**默认**。 |
| `manual` | 脚本导出 prompt 到 `out/prompts/`，人工在平台渲染后把成片放回 `out/videos/<job_id>.mp4`。慢，但不需要 API 凭据。 |
| `ark` | 火山方舟 Seedance，需 `ARK_API_KEY`。**会消耗付费额度**，调用前须获得额度所有者明确同意。 |

实际渲染须显式指定 `--model`（模型 ID 或接入点）、`--ratio` 和 `--duration`。
manual 模式在平台上使用同样参数。一次运行的两个组使用相同配置，每条结果记录请求参数。
方舟模式使用 [官方 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api)
的独立参数字段，并记录查询响应中可用的模型、画幅和时长。不同配置的实验使用独立目录。
`--out-dir` 可用于准备、渲染、生成评分表和聚合，各步传入同一目录。

方舟提交后立即将任务 ID 写入 `ark-tasks/`。中断后用相同命令重跑，已有任务继续查询，
已完成的成片直接复用。若要从金丝雀批次扩展到全量，保持目录、提示词和参数一致，
移除 `--limit`。若 POST 响应丢失，记录会停在 `submitting`，重跑会提示到方舟
控制台核对。查到任务后，可在对应 JSON 中填入 `task_id`，将 `status` 改为
`submitted` 再续跑。确认平台从未接收该请求后，才可移除对应记录并重试。
旧版方舟结果应先核对并保留在原目录。

## 评分为什么这样设计

见 `rubric.md`。三个要点：

1. **只评指令遵循 + 技术缺陷，不评美学** —— 美学主观、跨评分者不一致、无法归因到
   某条 prompt 改动，放进 A/B 只会制造噪音。
2. **二元判定**（pass/fail/n/a），不用 1–5 分制 —— 模糊分数会把美学偏好混进来。
3. **盲测**用打乱的样本顺序和匿名成片。映射单独存入 `_blind_key.json`，由聚合脚本读取。

## 已验证到哪一步

- ✅ 已用本地模拟成片验证匿名文件路径和盲测映射。
- ✅ 已用构造评分验证完整配对、缺片、缺项和适用评分项不一致的处理。
- ❌ **真实渲染未跑** —— 本机无任何 Seedance / 火山方舟 / Higgsfield 凭据。
  这一步需要额度所有者提供凭据或走 `manual`。

在真实渲染跑完之前，**不要宣称这个 agent 达到了商用级**。管道就绪 ≠ 质量已验证。

## 第二个实验（已暂停）：会议层到底有没有用

`references/meeting-protocol.md` 的会议层把「神仙会」移植成 agent-to-agent 评审层。
它的**正当性建立在降低下尾风险，而非提高峰值质量**上，因此不能因为"看起来更严谨"就采纳——
必须走同一套 A/B：

| 组 | 内容 |
|---|---|
| **A** | 完整工作流 + 会议层（提案会 / 人物会 / 评审会） |
| **B** | 同一需求，跳过会议层，其余相同 |

与首个实验的区别在**主指标**：Step 5.5 测的是出片缺陷数，会议层测的是
**首次通过率 / 返修轮次 / 跨镜头一致性 / 反 slop 命中率**，并要求显式定义**下尾指标**
（建议取主指标的 **P25 分位数**，而非均值）。

**五要素阈值骨架**（具体数字须由基线标定；未预设阈值的 A/B 不构成上线判据）见
`references/meeting-protocol.md` §12。

> ⏸️ **当前状态：暂停**（2026-09-12 由用户决定）。会议层**已在短剧 / 长片模式下默认开启**
> （见 `references/meeting-protocol.md` §0.1），但**收益仍未验证**——这是有意接受的取舍：
> 先上线拿真实使用数据，暂不为它单独跑 A/B。恢复实验时按下述设计走。

恢复实验时可以先做文本交付对照，固定宿主模型、输入需求和产出要求。按双人对话、
多人调度、跨集状态变化分别选用例，记录首次验收率、人工要求修改的轮数、耗时和输入输出 token
（含子 Agent）。让评审者按相同口径盲评两组交付件，再比较各类任务的质量和成本。

⚠️ 会议层有多智能体量级的 token 开销，且其预算上限（≤ 主流水线单次 **30%**）是**设计建议、
无实证依据**。**在 A/B 出结果之前，不要在任何对外材料里宣称它提升了质量。**

## 金丝雀与成本纪律

> 蒸馏自 Emily2040/seedance-2.0（MIT）`evals/capped-rendered-pilot.md`。真实渲染涉及真金白银，
> 开跑前先立四条纪律：

1. **金丝雀先行**：全量 24 槽位开跑前，先跑 4 条金丝雀用例（覆盖
   single-shot / short-drama / I2V / 多人 blocking 四种失效形态）。金丝雀内
   技术失败（授权拒/参考失效/超时）超过半数 → **停跑并如实记录"不完整"**，
   不许换简单用例充数让实验"看起来成功"。
2. **成本上限先于调用**：跑之前先定 `单次渲染价格 × 最大次数` 的上限数字。
   价格查不到 = 不开跑，不猜价、不"跑几个试试"。
3. **用例冻结**：`--prepare` 生成槽位后用例即冻结；跑的过程中不得替换或
   新增用例——那是在改实验，不是在跑实验。
4. **计划与观测物理分离**：计划表（槽位、探测点）与观测结果（评分表、缺陷
   计数）分开存；**计划行禁止事后抄进结果表冒充观测**。聚合只认观测行。

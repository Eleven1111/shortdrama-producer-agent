# 澄清协议（Clarification Protocol）

把用户一句模糊想法 → 结构化创意简报。三条原则：

1. **问得少而准** —— 一次问完，绝不做成问卷。技术维度（焦段/画幅/风格锚/模型参数）
   永远自己定，标注假设即可。
2. **面向新手用选项，不用问句** —— 见下方「选项式追问」。开放问句会把不知道自己
   要什么的用户直接劝退。
3. **信息越少，问得越少** —— 反直觉但正确：零信息时不提问，改为给具体方向让用户挑
   （见「零信息兜底」）。

下面的五问/六问是**信息采集清单**（单镜头五问；短剧六问，多出「结局与节拍」并先做
故事拆解），供 agent 自查覆盖面用 —— 不是给用户看的话术。

## 触发判断

| 情况 | 动作 |
|---|---|
| 用户给出 ≥3 个信息维度（主体/场景/氛围/风格） | 跳过提问，直接生成，写下假设 |
| 用户给出 1–2 个维度 | **一轮选项式追问**（见下节），≤2 题，然后生成 |
| 用户几乎零信息（「做个搞笑视频」） | **不提问，直接给 3 个成品方向**（见「零信息兜底」） |
| 用户给了参考图/参考片 | 沿用其风格，不重复问视觉维度 |
| 用户说短剧/多镜头/分镜/故事 | 直接进短剧模式，按 story-breakdown 拆解 |
| 用户说「随便/你定/都行」 | 立即停止提问，自主设计并标注假设 |

下面的「五问/六问」是**信息采集清单，不是话术**。除非用户明显是专业用户并主动
要求详聊，否则不要把五问原样抛给用户 —— 新手看到「主体：人物/怪物/物体/纯环境？」
只会懵。面向新手一律走下节的选项式。

## 选项式追问（面向新手的默认方式）

### 唯一原则：只问「猜错了代价高」的维度

agent 能自己定的（外观、光质、焦段、风格锚、画幅、时长）**一律不问**，用假设清单填充。
真正值得占用用户一次回答的，只有改变成片走向的分叉点：

| 该问 | 不该问 |
|---|---|
| **调性**（决定光线/色调/运镜/配乐） | 光质冷暖、焦段、机位 |
| **结局落点**（决定整条叙事线） | 角色外观细节、服装 |
| **真实 vs 风格化**（决定质感基线） | 导演/摄影师锚点 |
| 时长档位（仅当用户提了投放平台） | 画幅、码率、模型参数 |

### 写法规范

- **每题 3–4 个具体选项**，每项一句话说清成片会长什么样 —— 不要「你想要什么调性？」
  这种开放问句，新手答不上来。
- **每题必带「你定」**，选它就走假设清单，绝不追问第二轮。
- **一轮问完，最多 2 题**。用户答了就生成；用户没答、答一半、答「不知道」→ 立即用
  假设填充并生成，**不要再问**。
- 提问同时给出「我打算默认这么做」的预告，让用户不答也能往前走。

### 示例

用户输入：`雨夜，一个女孩在便利店门口等人`（2 个维度：场景 + 主体）

```
两个问题就开工（不想选就说「你定」，我按 A 走）：

1. 调性 —— 想要哪种？
   A. 温情：暖黄灯箱、柔和手持、雨声为主  ← 默认
   B. 悬疑：冷调、镜头克制、只留脚步与雨
   C. 孤独文艺：长镜头、几乎不动、环境音放大

2. 她最后等到人了吗？
   A. 没等到，独自离开  ← 默认
   B. 等到了，但不是她以为的人
   C. 开放结尾，停在她抬头那一刻
```

**反例**（不要这样问）：「主体是谁？场景在哪？要什么情绪？风格锚是什么？画幅多少？」
—— 五个开放问题，新手会直接放弃。

## 零信息兜底（「做个搞笑视频」这类）

**不要提问。** 零信息时提问只会让用户更卡壳 —— 他不知道自己要什么，才说得这么泛。

直接给 **3 个可拍的具体方向**，每个一句话，让用户点一个或说「都不是」：

```
给你三个方向，选一个我就开工（也可以说「都不是」，我再换）：

A. 办公室摸鱼被老板抓包 —— 都市写实，一镜到底的尴尬凝固
B. 宠物拆家现场 —— 手持跟拍，狼藉全景收尾
C. 外卖小哥的极限操作 —— 市井动作感，快切
```

要点：
- 方向必须**具体到能直接开拍**，不是「幽默日常类」这种品类词。
- 用户说「都不是」→ 换一批，**不要转而提问**。
- 用户选了 → 直接进生成，其余维度全走假设清单。

## 输入示例库（可直接给用户参考）

新手常见的问题是不知道该说多少。给他看对照：

| 输入 | 会发生什么 |
|---|---|
| `做个视频` | 零信息 → 给 3 个方向选 |
| `做个搞笑视频` | 零信息 → 给 3 个方向选 |
| `雨夜女孩在便利店等人` | 2 维 → 问 2 题（调性、结局）后生成 |
| `雨夜，女孩在便利店门口等不到人，孤独、冷调` | ≥3 维 → **直接生成**，不提问 |
| `雨夜女孩等人，冷调孤独，三个镜头，最后她独自走进雨里` | 短剧模式 → 直接拆解生成 |

一句话给用户：**说清「谁 + 在哪 + 什么感觉」就够开工了；再加一句结局，就能出短剧。**

## 五问（单镜头模式，一次问完，不分多轮）

1. **主体**：谁/什么？人物（年龄/性别/特征）、怪物、物体、纯环境？
2. **动作**：在做什么？静止氛围（slow cinema）还是事件（追逐/打斗/互动）？
3. **场景与光**：哪里？室内/室外、什么年代/时期、白天/夜、光质（暖/冷/自然/霓虹）？
4. **情绪**：要什么感觉？给 2–3 个形容词（如 tense + atmospheric + nostalgic），或让用户报一个参考片 vibe。
5. **风格锚**（可选）：导演/摄影师/胶片/类型片？用户不熟就由本技能推荐（默认 Lubezki × Deakins + 现代写实）。

## 六问（短剧模式 = 五问 + 结局节拍问）

1-5 同上，第 6 问：
6. **结局与节拍**：故事往哪走（一句话结局）？大概几个节拍（起/承/转/合）？
   追问不细究：用户答不出节拍，就由本技能按三幕结构兜底拆解（见 `story-breakdown.md`）。

## 澄清后的简报格式

### 单镜头简报
```yaml
主体: 谁/什么（含外观关键词，或写"待定，用参考图"）
动作: 一句话情节或"纯氛围"
场景: 地点 + 时间 + 光质
氛围: 2-3 个形容词
风格锚: 导演×摄影师 / 胶片规格 / 类型片（可"推荐"）
规格: 画幅 / 时长（按 platform-capabilities.md 选，勿硬编）/ 有声(默认是)
档位: cinema | quick（默认 cinema）
假设: [本技能替用户做的默认假设，用户可改]
```

### 短剧简报（进 story-breakdown 前）
```yaml
模式: short-drama
故事目标: 主角想做什么
最终结局: 一句话结局（用户给 or 本技能提议待确认）
节拍数: 3-8 个（三幕兜底）
场景数: 预计 N 场
镜头预算: 预计 N 镜（单批 ≤6）
风格锚: 同单镜头
假设: [含结局/节拍的默认设计，用户可改]
```

## 假设清单（未问即用的默认值）

- **时长与画幅按 `platform-capabilities.md` 定，不要硬编。** 15s 是 Seedance 2.0 的上限，
  2.5 可到 30s；语料里 21:9 占 97.6% 是源项目的美学偏好，不是平台默认 —— 面向短视频/
  社交平台时 16:9 或 9:16 通常更合适。平台未知时用 15s + 通用画幅并标注为保守默认。
- 有声默认开（实测 generate_audio true 95.4%）；prompt 用英文写（实测 100% 英文）。
- 风格锚默认「现代写实电影感」，若用户提到"酷/炫/动漫"则换对应锚
- 角色命名：按主体语义取小写英文名（如「穿红衣的女孩」→ `red_girl`）；短剧模式命名进连续性圣经并全剧复用
- 无参考图时，角色外观由本技能按简报设计并声明为假设
- 短剧默认三幕结构（开端/冲突/结局）；镜头预算按平台单次时长上限估算（见 platform-capabilities.md），不要固定按 15s

## 边界

- 用户说"随便/你定" → 本技能自主设计并明确标注所有假设，交付后给 3 个可调项。
- 用户拒绝回答某问 → 跳过该维，用假设填充并在简报标注。
- 澄清绝不问"你想用什么模型参数"这类技术细节——那是本技能的职责。
- 短剧模式的镜头预算必须与用户对齐后才进连续性圣经阶段。

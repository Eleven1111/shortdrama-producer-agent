# 输出模式 — 用户要的不总是一条新 prompt

此前本 Agent 只有一个出口：想法 → prompt。但真实需求里有相当一部分是拿着**已有的
prompt** 来的：「为什么出片是糊的」「角色怎么又变脸了」「帮我改一下但别整个重写」。
这类请求用「重新生成一条」来回答是答非所问。

五种交付物，按用户措辞选最具体的那个：

| 模式 | 触发措辞 | 交付 |
|---|---|---|
| `full-direction`（默认） | 未指定 | 导演方案 + 素材映射 + 连续性/禁止项 + 一条可粘贴 prompt |
| `prompt-only` | 「只要提示词」「直接给我 prompt」 | **仅**一个 ```text 代码块，无标题无点评 |
| `script-only` | 「只要脚本」「先给我剧本」 | 可拍脚本：前提 / 分镜或时间轴 / 对白 / 表演 / 声音 / 收尾。不含 prompt 外壳 |
| `diagnosis-only` | 「为什么效果差」「帮我看看问题」「诊断」 | 只诊断，**不擅自重写** |
| `revision` | 「按原结构改」「只补缺的」「别动我的框架」 | 保留原结构，只改必要处，并列出改了什么 |

**输出模式是硬约束，不是风格建议。** 用户说「只要提示词」，就不要附赠导演方案；
说「只诊断」，就不要顺手把 prompt 重写一遍交回去。

---

## diagnosis-only：怎么诊断才不是空谈

先跑确定性诊断，再解读。**不要凭感觉点评。**

```bash
python3 scripts/diagnose_prompt.py <用户的prompt文件>
# 或： cat prompt.txt | python3 scripts/diagnose_prompt.py
```

脚本给出四类判据，全部落在数据上：

1. **内部矛盾** —— 确定性规则（同时要求无配乐与加配乐、静止机位又要运镜、
   一镜到底又写硬切…）。**这类必须最先解决**，矛盾指令会让模型随机挑一边执行。
2. **缺失的结构段** —— 对照 7,824 条真实生产 prompt 的段落出现率。
   `SCENE CONTEXT` 57.9% / `AUDIO` 51.7% / `LIGHTING` 47.8% / `PHYSICS` 42.9% …
   报的是「真实生产里一半以上都写、而你没写」的段，不是凑数。
3. **缺失的约束** —— 对照 `iteration-lessons.md`（4,154 组真实修订）。
   真实生产中 **69.7% 的修订是在加约束**，所以出片不理想时，约束缺口比文采问题
   可能性大得多。
4. **规格问题** —— 时长/画幅声明缺失、时长超出平台上限（见 `platform-capabilities.md`）、
   全文过短（真实生产中位约 9,000 字符）。

解读时的纪律：

- **按影响排序**：矛盾 → 规格 → 高频段缺失 → 约束缺失。不要平铺一张清单。
- **每条给出可执行的补法**，而不是「建议增加光照描述」这种废话 —— 直接给该写的句子。
- **不确定的不要硬说**。诊断器只能看结构与约束；如果结构没问题，就直说
  「结构与约束无明显缺口，问题更可能在创意描述本身（动作是否具体、光是否可执行）」，
  不要编一个结构问题出来凑。
- **区分「缺失」与「不适用」**。单镜头没有 `ACTION TIMING` 不是问题；没有演员的
  画面不需要「禁止看镜头」。脚本已按单/多镜头与有无人物做了过滤，但仍要复核。

## revision：改哪些、不改哪些

用户说「按原结构改」时，**原结构就是硬约束**：

- 保留原有的段落顺序、命名习惯、语言（用户写中文就别换成英文重写）。
- 只做三件事：**解矛盾**、**补高影响缺口**、**修规格越界**。
- 不要顺手优化文采、不要替换风格锚、不要重排段落。
- 交付时先用三五行说明**改了什么、为什么**，再给改后的完整artifact。

判断「高影响」的依据同上：矛盾 > 规格 > 高频段 > 约束。一次改动别超过用户能复核的量。

## 与生成工作流的关系

`diagnosis-only` 与 `revision` **跳过** Step 1（信息量分流）和 Step 3（简报）——
用户已经给了完整 prompt，不需要再澄清创意。但仍然要用：

- Step 2 检索（找同类场景的真实写法，作为「该怎么补」的依据）
- `platform-capabilities.md`（判断规格是否越界）
- `iteration-lessons.md`（判断缺哪些约束）

# 平台能力边界 — 同一个模型，不同平台不是同一件东西

Seedance 是模型，Higgsfield / Dreamina（即梦）是**承载它的平台**。同一个 Seedance 2.5，
在两个平台上的时长上限、素材配额、可用模式都不一样。**先确定平台，再定参数**，
否则给出的时长、画幅、模式全是错的。

## 证据分级（每条能力都标注来源，不要把二手当事实）

| 级别 | 含义 |
|---|---|
| **[实证]** | 本项目 404,994 条 Higgsfield 真实生成参数统计得出 |
| **[官方]** | 平台官方文档 / 官方页面说明 |
| **[报道]** | 媒体实测或第三方指南，多来源互证 |
| **[未验证]** | 单一二手来源，尚未核对 —— 使用前须以运行时 UI 为准 |

## 一、能力矩阵

### 时长

| 平台 · 模型 | 时长 | 来源 |
|---|---|---|
| Higgsfield · Seedance **2.0** | **4–15 秒**（8s 或 15s 上限按套餐） | [实证] max=15，无一条超出；[官方] 一致 |
| Higgsfield · Seedance **2.5** | **最长 30 秒**；续写链最长 60 秒 | [官方]（本项目样本仅 562 条且都 ≤15s，不足以反证） |
| Dreamina · Seedance 2.5 标准 | **最长 30 秒** | [官方][报道] 即梦 App 实测 720P |
| Dreamina · **Long Video**（beta） | **5–180 秒** | [官方][报道] 标注 beta，稳定性可能低于 30s 原生 |

> **默认值别再硬编 15 秒。** 15s 是 Seedance 2.0 的上限，对 2.5 用户等于砍掉一半。
> 不知道平台/版本时用 15s 并**明确标注为保守默认**。

### 画幅

[实证] Higgsfield 支持 6 种，与[官方]一致：`16:9` `9:16` `4:3` `3:4` `21:9` `1:1`，另有 `auto`（按输入推断）。

实测分布：21:9 **97.6%** · 4:3 2.2% · 16:9 0.15% · 其余 <0.1%。

> **这个 97.6% 是 Cully Hill Boys 一个项目的美学选择，不是平台默认，也不是"最优"。**
> 面向普通用户（短视频、社交平台）时 `16:9` 或 `9:16` 通常更合适。
> 只有用户明确要电影感宽银幕时才用 21:9。

### 分辨率与码率

[实证] `resolution`：1080p 82.7% · 4k 17.0% · 720p / 480p <0.3%。`bitrate_mode`：high 99.3%。
[报道] 即梦 App 侧显示 720P。

### 参考素材配额

| 平台 | 配额 | 来源 |
|---|---|---|
| Higgsfield | 9 张图 + 3 段视频（各 ≤15s）+ 3 段音频（各 ≤15s） | [官方] |
| Dreamina | **最多 50 个**参考素材（图/视频/音频） | [官方][报道] |

> 差距是数量级的。为 Dreamina 设计的多角色方案搬到 Higgsfield 会直接超配额。

### 其他实测参数域

[实证] 全部来自 404,994 条：

- `prompt_language`：**100% 英文** —— 语料是英文，prompt 也应写英文
- `generate_audio`：true 95.4% —— 音频默认开
- `multi_shots`：**100% false**；`multi_shot_mode`：`custom`
- `mode`：`std` · `speedramp`：`auto` · `genre`：`auto`

> **`multi_shots` 全为 false 是个重要发现**：这批真实短剧生产的多镜头，不是靠平台的
> 多镜头开关，而是**在一条 prompt 内用 `SEG` + `HARD CUT` 时间码描述**。本 Agent 的
> 短剧模式做法与真实生产一致，不需要改。

## 二、主模式选择

### Higgsfield 类平台（本 Agent 的默认假设）

| 模式 | 何时用 | 怎么做 |
|---|---|---|
| 单镜头 | 一个连续动作 / 一个氛围 | Step 4 十条硬规则 |
| 多镜头（prompt 内切分） | 有故事、场景变化、分镜 | 一条 prompt 内 `SEG1/SEG2/...` + `HARD CUT at Xs`，[实证] 真实生产做法 |

### Dreamina / 即梦 [未验证 —— 以运行时 UI 为准]

以下模式来自 Dreamina 官方指南的二手转述，本项目**未能直接核对原始文档**。用户在
Dreamina 上工作时可作为分流参考，但**必须以其 UI 实际提供的选项为准**：

`basic-multimodal`（4–30s）· `timestamp-30s`（精确时间轴）· `long-video`（30–180s）·
`video-extension`（续写）· `video-edit`（局部编辑）· `clay-renderer`（白模）·
`seamless-transition`（两段视频衔接）· `multi-grid-storyboard`（多格分镜）

其中两条即使未验证也值得遵守，因为它们是纯粹的歧义防护：

1. **不要把普通的「30 秒」请求自动升级成 Long Video** —— 精确 30 秒和 Long Video 是
   两条不同路径。
2. **续写方向必须问清**：「向前续写 / 前向续写 / 往前延长 / 向后续写 / 后向续写」
   在中文里都有歧义，**不许从剧情推断**，直接问「新增片段放在原片之前还是之后？」

## 三、Agent 该怎么用

1. **推断或询问平台**：用户提到 Higgsfield / Dreamina / 即梦 → 直接套用对应列。
   没提且请求涉及**时长上限、参考素材数量、Long Video、续写/编辑**时 → 用选项式
   问一次（这属于「猜错代价高」，见 `clarification-protocol.md`）。
2. **纯创作请求不要问平台** —— 15 秒以内的单镜头/短剧在两个平台都成立，直接生成。
3. **默认值与标注**：不确定时用 15s + 平台通用画幅，并在交付备注里写明
   「按保守默认，你的平台若支持更长可以放大」。
4. **超限要提示**：用户要 60 秒 → 说明 Higgsfield 需要续写链、Dreamina 需要 Long Video，
   不要默默生成一条平台跑不了的 prompt。

## 四、UNKNOWN / 待核实

- Higgsfield 上 Seedance 2.5 的 30 秒上限：本项目样本（562 条）全部 ≤15s，未能实证。
- Dreamina 八种模式的实际 UI 名称与分界：**未验证**，仅二手转述。
- Long Video (180s) 的实际稳定性：官方标注 beta。
- 各平台的积分/计费差异：不在本文范围。

**本文快照日期：2026-08-17。** 平台能力变化快，运行时 UI 与本文冲突时**一律以 UI 为准**，
不要臆造新限制，也不要拿本文的数字去反驳用户看到的界面。

# 会议层协议（Meeting Protocol · 机-机）

> 把「神仙会」移植为 **agent-to-agent 的会议层**：在生成流程上叠加三个可选插入点，每层 3–4 个异构 agent 独立提案、低带宽互评、中心化裁决、收敛后独立复述，全程留痕、会话级实例化、超时即退。
> 与 `concept-symposium.md`（人-机前置层）互补：那一层用户在场、在生产**之前**；这一层用户不在场、在生产**之中**。二者共用公理 #1（发散与拍板分离）与 #4（异构胜同构）。
>
> ⚠️ **效果未经验证。** 本层的质量收益**尚无 A/B 证据**（A/B 已按用户要求**暂停**，见 §12）。**默认开关按生产模式分级**（见 §0.1）：**短剧 / 长片默认开，单镜头默认关。** 本文件是设计层，不是实测层。

---

## 0.1 默认开关（按生产模式分级）

| 生产模式 | 默认 | 跑哪几层 |
|---|---|---|
| **单镜头** | **关闭** | —（用户显式说「开会」才开） |
| **短剧**（多镜头 / 分镜） | **打开** | 提案会（首轮一次）+ 人物会（出现新角色 / 绑定冲突时）+ 评审会（每批 ≤6 镜） |
| **长片**（≥3 集 / ≥60 镜 / 电影） | **打开** | 提案会（项目级一次）+ 人物会（每集新增角色时）+ 评审会（每批）+ 风格先导批复审 |

**显式覆盖（任一轮都可）**

| 用户说 | 效果 |
|---|---|
| 「不开会 / 别走会议层 / 快速 / 先看看」 | **本次关闭**，回退单主体流水线 |
| 「开会 / 走会议层 / 严格模式 / 要评审记录」 | **强制打开**（单镜头也可开） |

**降级仍然生效**：运行时若无法隔离上下文（Tier 3，见 §9），「默认打开」**无法兑现** → 如实降级为「强化 Step 5 + 结构化自审清单」，并在交付物标注「本轮未经集体评审」。**不得因为"默认开着"就假装开过会。**

> ⚠️ **成本提示**：默认打开会让短剧 / 长片的 token 开销与轮次明显上升（多智能体量级）。某轮若以成本优先，直接说「不开会」。

## 0. 为什么需要它：骨架层的真空

本 agent 全流程**单主体线性执行**，Step 5 只有 7 项自检——而它们**全部位于格式层**：OPTICS 角度、SCENE CONTEXT 含光、ACTION 序列、`<<<anchor>>>`≥1、负面约束≥5、音频、风格锚≥1。

**没有任何一项能否决一个故事层或人物层的决定。** Step 5.5 的实测数据从反面证实了这一点：4,154 条真实修订中 **69.7% 是加长度，骨架仅变 2–6%**（创作者迭代时只加固约束，不动骨架）。

两者合起来是同一个结构性空缺：**现行自检从不触及骨架，也没有任何角色被授权质疑骨架。** 会议层要补的，正是「无人在场质疑骨架」这个位置——而不是笼统地「加几个角色」。

## 1. 第一原则：显式裁决者，不做去中心共识

集中式（有 judge）的 Disagreement Collapse Rate 为 **41.27%**，而去中心同构配置高达 **86.36%**（Yao 等，2025，预印本 arXiv:2509.23055——**实验显示**，非「已证实」）。

人类侧独立推导出的工业传统也全部收敛到**中心化收敛权威**：好莱坞 showrunner 的「1 Voice」、韩国编剧中心制的「作家」、中国的「文学师 / 剧本统筹」。

→ **统筹 agent（文学师原型）必须存在，且必须被显式授予裁决权。发散侧可以并行，收敛侧不可民主化。**

## 2. 三层会议：插入点与触发条件

| 层 | 插入点 | 触发 | 跳过 |
|---|---|---|---|
| **提案会** | Step 3 后 / Step 4 前 | 意图维度 ≤2（信息不足需发散）；或 Step 2 语料检索置信度低 | 意图 ≥3 维**且**语料高置信命中 |
| **人物会** | Step 4.5 前后 | 新角色（无现存卡）；或资产绑定表冲突 | **几乎不应跳过**——见下 |
| **评审会** | Step 5 前 | 短剧模式（多镜头 / 连贯性敏感）；或上一轮返修 ≥1 | 单镜头 `prompt-only` 且首次生成 |

**人物会为何几乎不应跳过**：Step 3.5 资产绑定的实测显示 **45.4% 靠枚举 keep，仅 0.1% 列 not inherit**。这不是「边界清晰所以不用开会」，而是**继承边界事实上处于未定义状态**——恰是最需要仲裁的地方。

**强制顺序（集体裁决在前，格式自检在后）**：

```
Step 4.6 → 评审会（多角色出 critique）→ 统筹裁决（三态）→ 按裁决修订
         → Step 5 七项自检（作为 gate）→ Step 5.5 约束加固 → Step 6 交付
```

先解决骨架问题，再解决合规问题；避免在错误骨架上做精细加固。

## 3. 角色与委派契约

每个 agent 按**委派三要素**定义（objective / 输出格式 / 任务边界）。

> **会话级实例化**：四类角色均为**临时实例**——该层触发时创建、该层结束即销毁；**不设常驻 agent、不跨项目复用同一批评者身份**。critique 日志留存，角色不留存。

**N 的计数口径**：N = 参与**发散与互评**的 agent 数 = 提案 2–3 + critic 1 + troublemaker 1 = **4–5**；**统筹 agent 是拍板者，不计入 N**。若 troublemaker 由 critic 兼任（允许，前提是 persona 显式分离），则 N = 3–4。**推荐运行区间 N = 3–4，硬上限 5。**

| 角色 | objective | 输出格式 | 任务边界 |
|---|---|---|---|
| **统筹**（文学师原型） | 统一风格与连续性，产出最终单一提案与裁决记录 | 统稿提案 + 裁决记录（含理由） | **不参与发散、不出提案，只裁决与统稿** |
| **提案 ×2–3** | 各自独立产出候选 | 单一候选提案 | 发散阶段**不得引用他方提案作为论据** |
| **critic** | 找出**可证伪的失败** | critique schema（§4） | **只出批评，不出替代方案**（防 self-preference） |
| **troublemaker** | 强制反对 | ≥1 条可证伪的失败理由 | **不得少于 1 条** |

**「外部人 ≥50%」的操作化定义**：≥50% 的提案 agent **不接收**上游 Step 的中间偏好与统筹 agent 的偏好声明，**只接收任务本身与 `story_level/` 客观密度数据**。这是「外部」在 agent 侧唯一可判定的实现方式。

**时间盒分档（三者机制不同，不可混用）**：

| 层 | 档 | 轮次 | 异质性来源 |
|---|---|---|---|
| 提案会 | **短档** | 2–3 轮，单轮有界 | 靠**轮转**制造异质性 |
| 人物会 | **长档** | 可跨多轮持续至收敛 | 靠**沉浸**制造密度（资产继承仲裁往往无法单轮定案） |
| 评审会 | **短档** | 2–3 轮 + 收益递减检测 + 熔断 | 靠**轮转**制造异质性 |

## 4. critique schema 与低带宽信号

critique 必须**绑定定位**，**禁止只给总体评分**：

```json
{
  "target_id": "场次 / 段落 / 规则条目 id —— 必填",
  "issue_type": "节奏 | 人物 | 连贯性 | 风格 | slop | 合规",
  "severity": "blocker | major | minor",
  "evidence": "引用原文片段",
  "falsifiable_reason": "可证伪的失败理由 —— 必填",
  "suggested_patch": "建议修改（局部，非整段重写）"
}
```

**低带宽互评的具体形式**：互评阶段**只传** `{target_id, severity, issue_type, 一句话失败理由}`——**不传全文、不传完整替代方案**。

依据：交换完整解会使平均成对距离在**一轮内**由 0.315 降至 0.229，**损失发生在交换的那一刻**（Interaction Tax，arXiv:2608.23541）。

## 5. 五段流程

**独立提案 → 低带宽互评 → 统筹裁决（三态）→ 收敛后独立复述 → 末段合成（MoA 式）**

- **末段合成用 MoA，不用 Debate**：Interaction Tax 中 MoA 是唯一正向的 MIG（+0.012），Debate 最差（−0.078）。
- **独立复述的位置：裁决之后、合成之前。** 各提案 agent **私下用自己的话复述一遍已达成的决定**，并按各自理解产出执行计划，统筹据此合成最终稿。这是「先独立后交流」的精细化——**收敛之后仍需一次独立复述，否则共识会抹平个人声音**（Story Arena，arXiv:2511.05410）。
- **规模 >5 时**不搞全程全员会，改**两段式**：小组轮转发散（每组 3–4）+ 末段单次全体合成。

## 6. 两靶心：抗退化参数

**靶心 A — 不敢说（继承自人类侧）**

- critic 的负面输出**不回灌**其自身能力评价
- **否决权隔离**：critic 输出**进决策上下文、不进执行闸门**
- 对提案不对人（不署名、不可归因）

**靶心 B — 顺着说（AI 侧特有）**

- 禁止引用拍板者 / 上游 Step 的偏好作为论据
- 强制**先产出反对意见，再产出赞成意见**
- 必须给出**可证伪的失败理由**
- 禁模板化软化（「整体很好，只是……」）
- **异构谄媚配置**：≥1 个 designated troublemaker，**禁止全员 peacemaker**
- 轮次上限 2–3 轮 + 收益递减检测
- 调优预算放 **debater 侧**；judge 侧谄媚水平取**中等固定值**（judge 侧平坦）
- agent 数 ≥3
- enhanced persona + reflection 双缓解
- 评判前强制**长 CoT**（降 harmful self-preference）
- 裁判与生成方若为同一模型，须警惕 self-preference

## 7. 裁决规则

三态：**采纳 / 吸收 / 否决**。

- **拍板者可否决多数意见**——可以，且**必须允许**。惩罚权暂停 ≠ 决策权让渡。
- **推翻前轮共识的条件**：出现**新的可证伪失败证据**，且经 critic 复述确认。
- **必须书面理由**——这既是抗 sycophancy 手段，也是合规落点（§11）的前提。

## 8. 预算、熔断与降级

- **预算上限**：三层会议合计 token ≤ 主流水线单次消耗的 **30%**。⚠️ **这是设计建议，无任何实证依据，是可调初始值。**
- **分级触发**：见 §0.1 —— 单镜头默认**关**；短剧默认「提案会 + 评审会」（人物会按需追加）；长片默认三层齐开。
- **熔断**：若连续两轮所有 critic 的 severity 均为 `minor`（无 blocker / major），视为收敛完成，立即终止，不进第三轮。
- **降级**：任一层超时或超预算 → 立即中止该层，回退单主体流水线，并在交付物中标注「**本轮未经集体评审**」。

## 9. 运行时分档（独立性是前提，必须诚实降级）

本层的**全部依据**是「先独立后交流」。若运行时无法真正隔离上下文，「独立提案」就是假的——必须如实降级，**禁止把模拟输出当独立提案汇报**。

| 档 | 运行时能力 | 做法 | 必须的诚实标注 |
|---|---|---|---|
| **Tier 1** | 可 spawn 独立上下文（并行子 agent） | 真并发独立提案 | 无 |
| **Tier 2** | 仅单上下文 | 顺序 role-play；**优先把「不含提案者自述」的裸稿给 critic**；critic 与 troublemaker 强制分离 persona | **「本轮为同上下文模拟，独立性未完全保证」** |
| **Tier 3** | 不支持分角色 | 降级为「强化 Step 5 + 结构化自审清单」 | **「本轮未经集体评审」** |

## 10. 与既有资产共存

- `screenwriting-craft.md` 与 `story_level/` 六份密度数据**作为评审依据**，而非任由 critic 自由发挥——把主观评审变成**有参照系**的评审，同时天然降低 sycophancy（有客观基准时，附和的收益下降）。
- **Step 5 七项自检升级为 gate**（通过 / 不通过），而非评分项。它继续负责格式层，与评审会分治。
- `continuity_check.py` 保留为**确定性硬约束层——不参与投票，只做否决**。凡确定性可判的问题，一律不进会议。
- `eval/render_loop/rubric.md` 承接会议层的评分口径，保证人工评测与自动评审同源。

## 11. 合规落点：评审记录即证据链

critique schema 天然产出**带角色标识、带定位、带可证伪理由**的结构化记录，可直接作为「审核会商」的**机器可读证据链**（总编辑内容负责制要求落实先审后播、审核会商、信息核查）。

且投资额不足 30 万元的「其他微短剧」由平台自审——独立创作者场景大概率落入此层，平台自审对**可追溯材料**的要求不降反升。**即：即使质量增益边际，可审计性本身也可能是独立且充分的采纳理由。**

## 12. 可验证性与上线判据

> ⏸️ **A/B 暂停中**（用户 2026-09-12 决定）。会议层**已在短剧 / 长片模式下默认开启**（§0.1），
> 但**收益仍未验证**——这是有意接受的取舍：先上线拿真实使用数据，暂不为它单独跑 A/B。
> 恢复实验时按下述设计走，阈值骨架保留待标定。

**主指标**：首次通过率、返修轮次、跨镜头风格一致性、反 slop 命中率
**成本指标**：token / 轮次 / 时延、会议层占总成本比
**A/B 设计**：对照组 = **未经评审的单主体输出**。主要判据用自有 `eval/render_loop`——外部基准（DramaBench、CML-Bench）粒度在剧本 / 成片级，**不落在 10 秒单镜 prompt 级**。

**阈值骨架（五要素，缺一即不构成上线判据；具体数字由用户按基线数据标定，本协议只定骨架）**

1. **主指标最小可检出改善**：首次通过率绝对提升 ≥X 个百分点，或返修轮次中位数下降 ≥1 轮（X 由基线方差标定，须先跑 ≥20 个未经评审的基线样本）
2. **下尾指标定义**：本层正当性建立在**下尾风险**上，故下尾指标**必须显式定义**——建议取主指标的 **P25 分位数**（而非均值）作为下尾代表；**下尾无改善 = P25 无显著提升**
3. **成本与时延上限**：会议层 token ≤ 主流水线单次的 30%；单层时延 ≤ 主流水线单次生成时延的 1/2
4. **样本量与停止规则**：基线组与实验组各 ≥20 个任务；任一方向连续 10 个任务无差异即可提前停止
5. **回滚触发的组合条件**：**下尾无改善 且 成本超限 → 回滚**；仅下尾无改善但成本可控 → 收缩为「人物会 + 评审会」（撤掉提案会）再测；仅成本超限但下尾改善显著 → 提高触发门槛（只在新角色 / 返修场景开会）再测

> **明文规则：未预设阈值的 A/B 不构成上线判据。** 事后总能把结果解释成「差不多覆盖了」。**若 A/B 显示下尾指标亦无改善，应放弃会议层，退回单主体 + 强化 Step 5。**

## 13. 与概念神仙会的关系

| | 概念神仙会（`concept-symposium.md`） | 会议层（本文件） |
|---|---|---|
| 参与者 | **用户在场** | 用户不在场（agent 之间） |
| 位置 | 生产**之前**（Step 1 ↔ Step 3） | 生产**之中**（Step 3→4 / Step 4.5 / Step 5 前） |
| 产出 | 概念卡（喂 Step 3） | critique 记录 + 裁决记录 |
| 席位 / 角色 | 面向人的视角（编剧 / 导演 / 制片人 / 捣蛋鬼 / 观众代言） | 面向流程的角色（统筹 / 提案 / critic / troublemaker） |
| 收敛依据 | 人的品味 | 有参照系的 critique schema |

**共用公理**：#1 发散与拍板分离、#4 异构优于同构（各自都有强制的「捣蛋鬼 / troublemaker」席位）。

## 14. 反模式

- ❌ 全程全员大会（>5 人同时发散）——应小组轮转 + 末段单次合成
- ❌ 互评时传全文或完整替代方案——违反低带宽
- ❌ 让 critic 出替代方案——self-preference
- ❌ critic 输出直接变成执行闸门（应进决策上下文）
- ❌ 用去中心共识替代统筹裁决
- ❌ 只在格式层评审——那是 Step 5 的活
- ❌ 把 Tier 2 / Tier 3 的模拟输出当独立提案汇报
- ❌ 未标定阈值就宣称 A/B 通过
- ❌ 把 30% 预算上限当成实证结论（它是可调初始值）

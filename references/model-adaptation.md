# 跨模型适配层（Model Adaptation）

> 框架萃取自 [zenstory-ai/drama-skills](https://github.com/zenstory-ai/drama-skills)（MIT）的 target-model-profile（九条能力轴）与 delivery-profile；模型画像为 2026-09 第三方对比数据的快照（**未逐一官方验证，置信度分级标注**；模型迭代极快，投产后以官方文档为准）。跨模型红线另萃取自 super-director FAQ。
> 与 `platform-capabilities.md` 的分工：那边管**平台外壳**（同一模型被不同平台包装后的时长/配额差异）；本文件管**模型方言**（不同模型的正文怎么改写）。

## 0. 定位

shortdrama-producer 的原生规范（OPTICS/`<<<锚>>>`/`—`分段/负面约束/英文正文）是为 Seedance 校准的。换目标模型时**不改工艺、只改方言**——运动配方/表演时序/光影语法/调度规则全部照用，变的只是九条能力轴的取值与正文写法。

## 1. 九条能力轴（换模型先逐条声明，禁止按"据说支持"改写）

| # | 能力轴 | 声明什么 | 正文怎么变 |
|---|---|---|---|
| 1 | 模型版本 | 具体到版本号（Kling 2.5 ≠ 3.0） | 只路由到该版本方言，不按名称相近套用 |
| 2 | 提示词方言 | 通用自然语言 / 原生结构字段 | 命中方言按其字段与素材标记写；语言标签≠方言 |
| 3 | 单次原生时长 | 最短-最长秒数 | 分镜时每镜落在区间内；短动作到位后 hold，长动作按闭合状态拆镜 |
| 4 | 参考条件方式 | 无 / 首帧 / 首尾帧 / 多槽参考（上限） | 见 §5 |
| 5 | 声音同轨 | same_pass / silent | 见 §4 |
| 6 | 画幅与分辨率 | 实际接受的集合 | 只写已接受的那一个，不罗列备选 |
| 7 | 正文长度上限 | 可接受字符数 | 超限先删参考帧已承载的重复描述；连续性锁面与逐字对白不删 |
| 8 | 运镜词汇 | 是否接受具名运镜术语 | 不接受时改写成可见的画面关系变化（主体占画比/边缘进出/遮挡关系），不是换术语 |
| 9 | 正文语言 | zh / en | 正文用该语言；逐字对白保留原口语语言，不翻译 |

**未声明时的回退写法**：按已接受的镜头边界写完整、自足、不依赖任何执行端特性的正文——不做分段、不罗列画幅备选、运镜用可见画面关系描述、声音写职责而非可执行指令。这样的正文在任何模型上都成立，只是没有针对性收敛。

## 3. 方言转换规则（Seedance 规范 → 其他模型）

1. **结构映射**：OPTICS/SCENE CONTEXT/ACTION 分段 → 通用自然语言模型**拍平成段落**（保留顺序：场景光线 → 锚定外观 → 动作链 → 运镜 → 声音）；Veo/Sora 吃结构化长文，可保留分段。
2. **参数值禁写是跨模型红线**：`85mm/f2.8/47°` 一律改写效果（`浅景深，背景虚化主体锐利` / `medium shot, eye-level`）——super-director 实测多模型不认数值。
3. **单镜单向运动**是跨模型红线：复合运镜必糊，拆镜。
4. **运镜词汇降级**（能力轴 8）：不接受具名术语的模型，把 `dolly-in` 写成"人物在画面中逐渐变大/背景向边缘退去"；`whip pan` 写成"画面快速横甩模糊过渡"。
5. **锚定系统**：`<<<名字>>>` 是纯文本约定，任何模型都可保留；但**首尾帧/参考条件弱的模型，锚定外观描述必须更完整**（参考帧承载不了的细节全部写进正文）。
6. **负面词**：多数模型支持简单负面列表；不支持的把关键负面转成正面约束写进正文（如"画面无叠加文字"→"纯净画面，无任何文字元素"）。
7. **spec header**：`Duration: X seconds. Aspect ratio: <ratio>. One continuous shot.` 按目标模型改写——有 UI 参数面板的（Kling/Runway/Pika）时长画幅走面板，正文不再重复；纯 prompt 驱动的（Veo/Sora/Seedance）保留。
8. **语言与对白引号（按模型分流，易踩反）**：中文系模型（可灵/海螺/即梦/万相）中文正文同样成立且更稳；逐字对白永远保留原口语语言。**引号规则三派**：Omni 禁引号（冒号引出，防渲染字幕）；Wan 要求引号+指名说话人；Sora/Kling 引号可选但须指名说话人。写错方向会直接诱发字幕渲染或对白丢失。
9. **音频指令写法因模型分层**：Seedance/Omni/H3 = 完整声音时间线；Kling 3.0 = 五段公式的独立音频分句；Runway = 音频开关+职责说明；Pika = 仅 SFX 提示；Vidu = 不写，配外部音乐模型。

## 4. 声音同轨差异

- **same_pass**（Seedance/Veo 3.x/可灵 3.0）：正文写完整声音时间线——封闭事件集合、逐字对白、事件间底声或静默、显式声明无配乐层。规则照 `directorial-craft.md` §3 执行。
- **silent / 音频弱**（Runway/Pika/Wan，及对白同轨弱的 Kling 2.x）：声音段改写**声音职责说明**（谁说话、什么环境声承担信息、转场声落点），服务后期配音与审查，不写成可执行指令；正文显式关掉字幕/文字叠加层（防模型自造字幕）。
- **对白预算逐模型校准**：4.1 字/秒是 Seedance 实测值；对白弱模型对白预算再砍半，或把对白挪到后期。

## 5. 参考条件方式 → 设定图协议映射

| 模型能力 | 我们的协议怎么接 |
|---|---|
| 无参考（纯文生） | 三格设定图协议跳过；锚定外观全量写进每镜正文（角色卡详写） |
| 首帧 | 首帧=设定图正视图渲染结果；正文只写从该起点开始的**变化**（motion-only） |
| 首尾帧 | 尾帧=状态机 end state 的投影；正文写过程，不得发明新结果 |
| 多槽参考 | 直接映射 reference-image-protocol：三格设定图/道具/场景图按槽位挂载，顺序与界面挂图次序一致；槽位超限按重要性取舍并说明放弃了什么 |

**互斥陷阱**：不少执行端首/尾帧输入与多槽参考互斥——此时整组统一走多槽参考，首帧也当参考素材送入，不要拆成"首帧+参考图"两套说明。

## 7. Gemini Omni 方言（Google 最新视频模型，官方文档蒸馏）

> 依据：Google Cloud 官方 best-practices / Gemini API omni 文档 / DeepMind prompt guide（2026-05 I/O 发布 Omni Flash，1.1 Flash API 2026-06 预览）。与 Veo 的根本差异：**Omni 继承 Gemini 的世界知识与推理，官方原话"不必像 Veo 那样在 prompt 里规定到细节——讲清要什么，让模型自己把细节带出来"**。

### 7.1 五维 prompt 结构（官方示例拆解）

```
[镜头景别与运动] + [主体] + [风格/情绪] + [光照] + [音频]
```
示例骨架：`A wide-angle tracking shot glides gently across...（镜头） revealing a colossal chrome bean（主体）, cinematic and awe-inspiring ambiance（风格）, as a brilliant sun crests behind（光照）, underscored by a majestic orchestral score（音频）`
- 风格维只需给情绪词，不用展开细节；光照必须答"光从哪来+什么质感"。
- **写少不写多**：漂移的修复通常是**补一条缺失的约束**，而不是加长描述。这与 Seedance 的"加长收紧"迭代方向相反——先加约束，再考虑加细节。

### 7.2 独有语法（其他模型没有的）

1. **对白不加引号**：用冒号引出——`A woman says: My name is Clara.`（引号会诱发模型把话渲染成字幕）。
2. **时间码语法**：`[0-3s] A person is walking [3-6s] They stop and turn [6-10s] They start running`；也可自然语言 `After 3 seconds, a woman enters the scene` / `At 5s the chorus starts`。做分镜节奏、快速剪辑序列时用。
3. **单场景强制**：短正文必须显式写 `In a single unbroken scene / single continuous shot / No scene cuts`，否则模型会自作主张叙事剪辑（它会"编故事"）。
4. **负面极简**：`No dialogue / No embellishments / No extra sound effects`——一行一条，不堆长负面列表。
5. **任意组合输入**：prompt 里直接引用文件——`Dynamic sci-fi film style video based on image_0.png. Elements light up similar to video_0.mp4 synchronized to the beat of the music from audio_0.wav`。图+视频+音频可同时作条件。
6. **视频续写**：`Extend this video` / `The scene continues`——每次 +10s，总长 ≤40s；模型读前 10s 作上下文（角色/光照/叙事连续），最后几帧会被无缝改接。
7. **会话式编辑链**：`Make this video anime` / `Add a cat that jumps onto his lap, he begins to pet it. Keep everything else the same.`——编辑指令要短，复杂长编辑指令反而引发意外改动。
8. **文字渲染可读**：Omni 能准确渲染画面内文字（招牌/字幕条/车牌），需要可读文字时直接写内容与位置；不想要文字时用无引号对白规则+负面 `No text overlays`。
9. **一致性双锁**：角色描述**逐字复用**（官方做法）+ **same seed 参数**。`<<<锚>>>` 的"逐字复用"思想在此天然成立：把角色卡描述块原样粘进每条 prompt，只改动作/场景部分。
10. **成本纪律**：先 360p 预览验证构想，选中后再升 720p/1080p/4K。

### 7.3 shortdrama-producer 规范 → Omni 方言转换

| 我们的规范 | Omni 写法 |
|---|---|
| `Duration: 15s. Aspect ratio: 21:9. One continuous shot.` | 单次 ≤10s → 超过 10s 的镜**拆两镜**（预算重排）或用 Extend 链（≤40s）；spec header 保留 `One continuous shot, no scene cuts` 字样（单场景强制） |
| `<<<name>>> — 外观描述` | 保留，同一角色描述块逐字复用每镜；用户走 API 时配 same seed |
| OPTICS `47°(≈50mm)` | 参数数值照删（`medium shot, eye-level`） |
| `—` 破折号分段 | 拍平为五维自然语言流；长正文不占优——约束优先于描述 |
| 负面约束列表 ≥5 条 | 压成 2-3 条极简 `No X` 行（No dialogue 需求除外）；其余负面转正面写法 |
| 对白预算 4.1 字/秒 | 同轨音频沿用；**冒号引对白、无引号** |
| 多槽参考资产 | 改用 `image_0.png / video_0.mp4 / audio_0.wav` 文件引用法，按挂载顺序编号 |
| 转场 hard cut / match cut | 短镜内不切（单场景强制）；跨镜转场走多镜拼接，或用时间码语法做镜内节奏 |
| 短剧 6 镜/批 | 每镜 ≤10s 重排预算；>10s 的戏剧节拍用 Extend 链（注意 Extend 会改接最后几帧，状态机 end state 可能被微调） |

- [ ] 漂移修复走"补约束"而不是"加描述"？

# 概念神仙会（Concept Symposium）

> 生成之前，先跟用户把概念"碰实"。
> 机制源自「神仙会 → 多智能体编剧室」研究（六公理）：神仙会不是一种组织形式，而是**寄生在正式流程之上的运行风格** —— 权威结构不变，只在一个临时窗口内悬置惩罚权，让发散充分发生，再靠"拍板"收敛。本文件把这条运行风格**翻译成人机协作**。

## 0. 定位：澄清协议的深度分支，不是替代品

| | 澄清协议 `clarification-protocol.md` | 概念神仙会（本文件） |
|---|---|---|
| 定位 | **快速通道**（默认） | **深度通道**（opt-in） |
| 交互 | 问 ≤2 个选项题 / 给 3 个方向 → 直接开工 | 结构化发散 → 用户拍板 → 收敛成概念卡 → 开工 |
| 适合 | 想快速出片、已有明确想法 | 想一起把模糊想法聊实、概念还没定 |
| 下游契约 | **同一个**：Step 3 简报 | **同一个**：Step 3 简报 / story-breakdown 目标与节拍 |

两条通道**输出同一份上游产物**。神仙会只是用一个更充分的对话过程把这份产物填满。默认走快速通道，神仙会绝不强加。

## 1. 六公理 → 人机版落地

原神仙会的角色映射：

| 原神仙会 | 人机版 |
|---|---|
| 参会者（多人）发散 | **Agent 发散**：切多个异构视角，产出互不参照的方案 |
| 拍板人收敛 | **用户拍板**：选 / 弃 / 合 / 再要。Agent 不得替用户拍板 |
| 组织者悬置惩罚权 | **Agent 声明免责**：明说"这里没有烂点子"，先接住再说 |

六条公理逐条落地：

| # | 公理 | 人机版机制 |
|---|---|---|
| 1 | **发散权与拍板权分离** | Agent 只发散（给候选），用户只拍板（选/合/否）。Agent **禁止**在用户表态前自行收敛成"最终方案" |
| 2 | **惩罚权临时悬置** | 开场显式声明 low-stakes：任何想法先被接住（yes-and），不评判、不否定；跑偏的想法只标注代价，不判死 |
| 3 | **先独立后交流 + 低带宽** | Agent 一次产出 K 个**互不参照**的独立方案（不自我审查、不彼此抄袭）；呈现时**一行一条**，低带宽 |
| 4 | **异构优于同构** | 用**结构不同的视角**（不是同一视角换措辞）：制片 / 编剧 / 导演 / 捣蛋鬼 / 观众代言 |
| 5 | **寄生而非重建** | 神仙会寄生在 Step 1 与 Step 3 之间，**不改动** Step 4 生成、Step 5 质检、短剧主链路 |
| 6 | **发散收敛异律** | 发散轮＝最大化差异、不筛选不排序；收敛轮＝显式标准、主动砍、给权衡 |

> **关键校正**（研究报告核心发现）：AI 侧的失败模式不是"不敢说"，而是**顺着说**（sycophancy）。所以「捣蛋鬼」席位**不是可选项** —— 每个发散轮**至少一条**真实的前提质疑，否则本轮视为未完成、重出。

## 2. 何时进入（触发）

**默认关闭。** 神仙会是 opt-in 深度通道，绝不强加给只想快速出片的用户。

| 用户信号 | 动作 |
|---|---|
| 明说「先聊聊 / 先一起想想 / 帮我头脑风暴 / 先别急着做 / 我们碰一碰 / 概念还没定 / 神仙会」 | **进入神仙会** |
| 1–2 维输入 **且** 用户表现出"想发展这个想法"（追问、犹豫、多轮补充） | Agent **用一句话提议**："要不要先开个概念神仙会碰实？不想聊我就直接开工。" 用户不接 → 走快速通道 |
| 零信息（"做个搞笑视频"） | **仍走澄清协议**的 3 方向兜底 —— 零信息开神仙会等于把用户丢进空白，更劝退 |
| 已有明确概念（≥3 维且不含糊） | 不进神仙会，直接生成 |
| 用户说「随便 / 你定」 | 不进神仙会，自主设计 + 标注假设 |

> **铁律**：一次会话最多**一次**主动提议。用户拒绝后不再提。

## 3. 参会席位（异构视角，按需裁剪）

Agent 一人分饰多种**结构不同**的视角。默认 5 席，快速会话可裁到 3 席（编剧 / 导演 / 捣蛋鬼）：

| 席位 | 它替谁问 | 它守什么 |
|---|---|---|
| **制片人** | 市场 / 平台 / 受众 | 能不能被看完、能不能被投、投放形态是什么 |
| **编剧** | 故事 / 人物 / 冲突 | 有没有戏核、价值有没有转折（对接 `screenwriting-craft.md` §1/§2） |
| **导演** | 影像 / 调度 / 可行性 | 这个想法拍出来"长什么样"、能不能一镜落地 |
| **捣蛋鬼** | 反方 | **强制**挑战前提（"如果反过来呢""这不成立，因为…"） |
| **观众代言** | 用户自己 | 每轮替用户守住"你到底想要什么"，防跑偏 |

**异构纪律（公理 #4）**：五个席位必须**真的不同**。判据 —— 把席位标签遮住，能猜出哪条出自哪个席位，才算合格；若两条只是同义改写，视为一个方案，重出。

## 4. 三幕流程

### 第一幕 · 摊牌（Framing，1 轮）

把用户给的碎片摊开，明确**只有哪些轴是真的还没定**。

```
我听到的是：{一句话复述用户的想法}
已经清楚：{1–3 条}
还悬着的岔路（只挑最影响成片的）：
  ① {轴} — A / B / C
  ② {轴} — …
（除这些之外，其余我按行业默认走，不打扰你）
```

规则：
- **只列真正改变成片走向的轴**（调性 / 结局落点 / 真实 vs 风格化 / 体裁承诺），最多 3 条。
- 技术维度（焦段 / 画幅 / 风格锚 / 模型参数）**永不进神仙会** —— 那是 Agent 的活。
- 用户不必逐条回答，随便说一句也算。

### 第二幕 · 开脑洞（Divergence，1–2 轮）

在悬着的轴上有**结构不同**的候选，让用户拍板。每席一条，格式固定：

```
① 【编剧】{一句话方案} → {这意味着成片是…}
② 【导演】…
③ 【制片人】…
④ 【捣蛋鬼】⚠ {一条前提质疑，不是方案}
⑤ 【观众代言】…
```

规则：
- 各条**互不参照**（公理 #3）：先各自独立成型，再一起呈现；禁止"A 改成 B 那样"。
- **不筛选、不排序、不推荐**（公理 #6 发散侧）：不给"我更推荐 ①"。排序是收敛轮的活。
- 捣蛋鬼那条**必须是真质疑**；只有附和 = 本轮未完成，重出。
- 用户回应成本最低：回一个编号 / 「①+③」/「都不对，但②那个方向」/ 一句话 —— 都算有效拍板。
- **再次发散**：用户说"都不对 / 再换" → 换一批（**不要转而提问**），最多共 2 轮发散。

### 第三幕 · 收官（Convergence，1 轮）

把存活的想法收敛成**一张概念卡**，显式写清权衡与被砍项。

规则（公理 #6 收敛侧，与发散轮**不同律**）：
- **主动砍**：明确说哪几条被砍、为什么 —— 不搞"都要"。
- **给权衡**：选了 X 就放弃 Y，说清代价。
- **可召回**：被砍项列出但不展开，用户一句话可召回。
- **这里才排序**：可以给"建议以 X 为主、Y 为调料"，但最终拍板仍归用户（公理 #1）。

用户确认即定稿；用户说"就这样、开工" → 立即定稿。

## 5. 概念卡（神仙会的交付物，直接喂下游）

```yaml
概念名: 一句话项目名
一句话前提: {主角} + {处境} + {走向}     # 三段式 logline（埃格里）
戏核: 抽掉它戏就不成立的那一个东西
核心冲突: 谁 vs 谁 / vs 自己，为何"必须现在"动
调性: {2-3 个形容词}                    # 决定光线 / 色调 / 运镜 / 配乐
结局落点: 一句话结局                     # 短剧必填
被采纳的视角: [来自哪个席位]
被砍掉的选项: [可召回，一条一句]
开放假设: [Agent 替用户定的默认，用户可改]
下一个动作: 单镜头 → Step 3 简报 | 短剧 → story-breakdown 目标 / 节拍
```

**与下游接口**：
- **单镜头**：概念卡 → 直接填 Step 3 简报（主体 / 动作 / 场景光 / 氛围 / 风格锚）。
- **短剧**：概念卡 → 直接填 `story-breakdown.md` 的「故事目标 / 最终结局 / 节拍」；`戏核` 与 `核心冲突` 供 `screenwriting-craft.md` §1/§3 使用。

## 6. 收口与打断

| 情况 | 处理 |
|---|---|
| 用户中途说「直接做吧 / 够了」 | 立即收敛为最佳猜，标注假设，进 pipeline，**不再追问** |
| 用户全程沉默式回应（只回单字） | 不追加提问；按最近一次拍板收敛，进 pipeline |
| 发散 2 轮仍无存活项 | 退回澄清协议的 3 方向兜底（通常意味着信息太少） |
| 概念卡定稿 | **退出神仙会**，进 Step 1.5 / 2 / 3 正常链路 |
| 用户要改已定稿的概念卡 | 只重开第三幕（收敛），不必重发两轮散 |

## 7. 与"自主默认"的关系

神仙会不推翻"自主优先"，而是**给愿意投入的用户一条深水通道**：

- **不进入**神仙会时，一切照旧：≥3 维直接做、1–2 维问 ≤2 题、零信息给 3 方向。
- **进入**神仙会后，主动提问配额解除，但提问必须**结构化、低带宽、每轮有明确产出**，绝不变成问卷。
- 自始至终，Agent **不替用户拍板**（公理 #1）；技术的活仍全归 Agent。

## 8. 反模式（不要这样）

- ❌ 把五问原样抛给用户 —— 神仙会是**给方案让用户拍板**，不是问卷。
- ❌ 在用户表态前收敛 —— 那是抢拍板权。
- ❌ 只出同构方案（换措辞）—— 违反 #4。
- ❌ 捣蛋鬼只附和 —— 违反 #2，且是 sycophancy 复辟。
- ❌ 发散轮里排序 / 推荐 —— 违反 #6（把收敛律串到发散轮）。
- ❌ 零信息时开神仙会 —— 用户更卡壳，走 3 方向兜底。

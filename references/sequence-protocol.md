# 序列协议（Sequence Protocol）

短剧模式下，镜头不是孤立的：**clip N 的结尾状态决定 clip N+1 的开头**。
只用于短剧模式；单镜头模式不涉及。

## 核心规则

1. **结尾→开头**：每镜 prompt 的结尾帧（end state）必须与下一镜的开头（start state）衔接——空间、动作、角色位置、道具状态连续。
2. **已接受镜头覆盖计划**：用户实际生成并接受的镜头是**唯一事实**。下一镜的 prompt 基于"上一镜实际结果"而非"上一镜计划"。用户反馈"这里不对"→ 修正后该状态进入 canon。
3. **被拒镜头不入 canon**：用户不满意的镜头不能作为下一镜的衔接来源；必须重拍到通过。
4. **批次内顺序生成**：同一批镜头按 1→N 顺序产出；跨批次（用户说"继续"）先回顾上一批最后接受镜头。
5. **连续性状态机**：每完成一镜更新状态（角色位置/道具状态/情绪基调），下一镜读取。

## 连续性状态机

```yaml
当前镜: <N>
上一镜接受: <N-1，end state 一句话>
角色位置: <谁在画面哪里>
道具状态: <关键道具当前状态>
场景光线: <当前光线基调>
情绪基调: <本镜氛围词>
```

每次生成新镜前，先输出/更新状态机（≤6 行），再写 prompt。

## 镜头衔接写法

### 方式一：延续（推荐，默认）
下一镜 prompt 开头直接承接上一镜结尾：
```
...（上一镜结尾的动作/位置描述）— CONTINUATION: <角色> continues to <动作>，
camera <新机位> now ...
```

### 方式二：时间跳跃（换场/蒙太奇）
显式声明跳变，仍保持视觉一致性（同角色同圣经）：
```
— TIME CUT: <时间差> later, same <scene>，<角色> now <新状态>（引用圣经状态轴）
```

### 方式三：转场特写（衔接道具/视线）
用道具或视线做桥：
```
— INSERT: close-up of <道具>（状态=上镜结尾）; pull back to reveal <新场景/新角色>
```

## 每镜 prompt 的序列字段

短剧模式的每条 prompt 在正文前加 3 行序列头（非正文，供人/工具核对）：
```
# shot N / total | 场 X | 衔接: <延续|时间跳跃|转场特写> from shot N-1
# start state: <一句话>
# end state: <一句话（下一镜要接的）>
```

## 边界

- 用户只生成单镜 → 不输出序列头。
- 用户重拍上一镜 → 以最新接受版为准更新状态机，继续向后。
- 跨镜长时间断档（如隔天继续）→ 先重读连续性圣经 + 状态机再写，不依赖记忆。
